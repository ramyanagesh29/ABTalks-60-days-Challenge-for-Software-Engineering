## 5. Engineering lessons learned
1. **Choose the right data structure.** A hash map can improve Two Sum from O(n²) brute force to expected O(n).
2. **Understand the algorithm.** BFS finds shortest paths in unweighted graphs; dynamic programming reuses results of overlapping subproblems.
3. **Debug systematically.** Reproduce the error, identify its cause, make a focused fix, and test edge cases.
4. **Design for maintainability.** Clear modules, README files, and consistent error handling make projects easier to work on.
5. **Measure before claiming optimization.** Benchmark results should come from actual runs under stated conditions.
6. **Communicate trade-offs.** Explain requirements, approach, complexity, limitations, and alternatives.
7. **Be honest about limitations.** A prototype is a useful milestone, but it is not automatically production-ready.
